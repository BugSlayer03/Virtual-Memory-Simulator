ABOUT THE PROJECT

The Virtual Memory Simulator is an interactive educational web application designed to demonstrate the concepts of virtual memory and page replacement in operating systems. The simulator allows users to enter a reference string, specify the number of available physical memory frames, and select a page replacement algorithm such as FIFO (First In First Out), LRU (Least Recently Used), or Optimal. It then processes the reference string step by step and visually represents how pages move between virtual memory and physical memory.

The simulator provides a visual representation of logical memory, physical memory, the page table, and virtual memory, making it easier to understand how pages are mapped to frames and how page faults and page hits occur. It also presents a step-by-step simulation table along with statistics such as the total number of page faults, total references, and hit ratio. The main objective of the project is to bridge the gap between theoretical operating-system concepts and their practical execution through an interactive and easy-to-understand visualization.

CONTIGUOUS MEMORY ALLOCATION

Contiguous memory allocation is a memory management technique in which a process is allocated a single continuous block of memory. This means that all the memory required by a process is placed in consecutive memory locations. The operating system keeps track of the starting address and the size of the allocated block to determine which memory locations belong to the process. Common techniques such as First Fit, Best Fit, and Worst Fit are used to decide where a process should be placed in available memory.

The major advantage of contiguous allocation is that it is simple to implement and provides fast access to the allocated memory. However, it can suffer from external fragmentation, where free memory is available but scattered across different locations, making it difficult to allocate a large continuous block. As processes are loaded and removed, these gaps can increase, reducing the efficient utilization of physical memory.

NON - CONTIGUOUS MEMORY ALLOCATION

Non-contiguous memory allocation allows a process to be divided into smaller parts and stored in different locations of physical memory. Unlike contiguous allocation, the entire process does not need to occupy one continuous block of memory. Paging and segmentation are common techniques used for non-contiguous memory allocation. In paging, a process is divided into fixed-size pages, while physical memory is divided into fixed-size frames. Pages can then be placed into any available frames.

Non-contiguous allocation improves memory utilization because free spaces in different parts of physical memory can be used instead of requiring one large continuous block. Paging also eliminates external fragmentation, although it can introduce internal fragmentation. A page table is used to maintain the mapping between logical pages and physical frames, allowing the operating system to locate the required page in physical memory.

VIRTUAL MEMORY

Virtual memory is a memory management technique that allows a system to execute programs even when their complete contents cannot fit into physical RAM at the same time. It provides each process with a logical address space that is larger than the available physical memory. The operating system divides the process into pages and keeps some pages in physical memory while the remaining pages can be stored on secondary storage, such as a disk. When a required page is not currently present in RAM, a page fault occurs and the operating system loads that page into an available frame.

When all physical memory frames are occupied and a new page needs to be loaded, the operating system must select an existing page to remove. This is handled using page replacement algorithms such as FIFO, LRU, and Optimal. In this simulator, the reference string represents the sequence of pages requested by a process, while the specified number of frames represents the available physical memory. The simulator visualizes the movement of pages between virtual memory and physical memory, updates the page table, and calculates page faults and hit ratio to demonstrate how virtual memory operates.
